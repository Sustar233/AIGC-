# 剧本转 AI 视频分镜

把剧本文字转成可拍、可生成、可剪辑、可继续迭代的短时长视频单元。忠于来源事实；不要把分镜工作变成剧情改写。

## 核心边界

1. 以本轮用户指令、上传资料、剧本文字和已确认设定为唯一事实来源，优先级按此顺序由高到低执行。不要继承示例内容、旧项目记忆或模型常识中的人物与世界观。
2. 不新增剧情、角色、台词、关系、武器、能力、伤势、胜负、关键道具或场景物件。允许修正明显错别字；只有用户授权时才压缩或润色台词。
3. 把抽象心理和潜台词转成可见动作、眼神、呼吸、停顿、重心或环境反馈，但不要让表演细节形成新的剧情行为。
4. 每次最多输出 4 个连续单元，每个单元不超过 15 秒。长内容继续分批，不一次性倾倒整集。
5. 让每个单元能够脱离上一单元独立交给视频模型生成：重述当前场景、全部出场人物、初始站位和必要的物理前情，不使用“承接上集”“同上”等代称。
6. 只在缺失信息会改变剧情因果、角色身份、战斗结果、台词属性或关键连续性时暂停提问。非关键空白采用最保守镜头方案，不擅自补设定。

## 网页端工作方式

1. 直接读取当前对话可见的附件和文字。没有剧本正文时，简短请求用户上传或粘贴；不要凭标题生成剧情。
2. 首次处理一集时，在内部建立“事实锁”和“连续性状态”。执行前必须阅读 [输入与连续性](references/input-and-continuity.md)。
3. 完成一批后，在输出末尾附一份精简的“批次连续性末态”，记录站位、朝向、轴线、道具、伤势、能力和场景破坏。后续“继续”时继承该末态。
4. 用户在新对话继续项目但没有提供前文时，请其同时提供原剧本相关段落和上一批连续性末态；不要猜测缺失状态。
5. 用户只要求分析、拆解或审查时，仅给分析，不擅自输出正式分镜或改写源剧本。

## 执行流程

### 1. 判定任务

识别集数、场次、处理范围和任务类型：

- 新建正式分镜
- 快速拆解
- 继续下一批
- 局部修改某单元或镜号
- 多人场景优化
- 战斗/追逐/能力交锋
- 剪辑 B 版或候补镜头

用户指定范围时严格服从；未指定时从最早未处理剧情开始，连续输出 1—4 个单元。

### 2. 锁定事实并检查冲突

提取当前任务所需的人物身份、台词与 OS、关系、场景、时间、站位、道具、外观锚点、惯用手、武器、能力源点、伤势、不可改变结果和禁改项。

只把会影响剧情因果、身份、时间线、空间成立条件或视觉连续性的矛盾视为阻断项。发现阻断项时列出证据并只问最关键的问题；没有阻断项就继续。

### 3. 拆分单元并估时

按剧情拍点、台词语速、动作因果和情绪落点拆成不超过 15 秒的单元：

- 正常对话：约 4 字/秒。
- 情绪台词：约 3 字/秒。
- 压迫、威胁、审判、冷声质问：约 2.5—3.5 字/秒。
- 震惊、哽咽、迟疑、悲痛：约 2—3 字/秒。
- 短促爆发型愤怒或惊叫：约 5—7 字/秒。

单句台词超过约 5 秒时，优先拆成“说话者主景 + L-cut 听者反应”；15 秒内仍无法自然演完时拆到下一单元。不要用不自然的极快语速硬塞。

### 4. 选择制作模式

- 快速版：普通拆解，每单元通常 3—4 镜，只保留剧情节点、必要站位、核心动作、台词与关键反应。
- 标准版：普通正式制作，每单元通常 4—6 镜，在关键台词和情绪转折加入有选择的表演细节。
- 精细版：复杂多人、连续战斗、高风险特效或重点场面；按风险增加镜头，不为普通对白滥加微表情。

用户指定模式时服从。混合批次按单元分别升级，不要因一个高风险单元把整批都写成精细版。

### 5. 按风险加载规则

- 所有正式分镜：阅读 [输出格式](references/output-format.md) 和 [质量检查](references/quality-checklist.md)。
- 对白、情绪、反应镜或重要台词：阅读 [表演与镜头](references/performance-and-camera.md)。
- 3 人及以上可见角色、队伍、围观或多人移动：阅读 [多人调度](references/multi-character-continuity.md)。
- 连续对攻、格挡、追逐、摔投、能力交锋或明确打戏：阅读 [战斗动作](references/combat-choreography.md)。单次挥击、短促推搡和普通走位只应用相关的力学与连续性规则。
- 剪辑版、B 版、候补镜头：阅读 [剪辑候补版](references/alternate-edit.md)。
- 用户未指定画风，或要求推荐画风：阅读 [风格选择](references/style-selection.md)。

### 6. 设计镜号

1. 每个镜号只表达一个核心因果动作或反应。攻击动作、绑定特效和受力结果可同镜出现，因为它们属于同一因果链；不要再混入无关反应。
2. 每镜只保留一个核心运镜。把景别、机位、运镜、构图、焦点和镜头功能写在“镜头语言”；把人物表演写在“画面描述”。
3. 角色移动后立即更新站位、距离、朝向和轴线。接触动作前先确认人物已经物理相邻。
4. 双人对峙和近身交锋锁定 180 度轴线与左右关系；越轴必须通过可见过轴镜头建立。
5. 台词、动作和反应按整数秒排列成连续时间轴，从 0 秒开始，合计与单元时长一致且不超过 15 秒。

### 7. 输出与迭代

严格套用 [输出格式](references/output-format.md)。默认给可直接复制使用的完整分镜，不先输出长篇创作说明。

收到修改意见时，只改受影响单元或镜号，并继承已确认的剧情节点、台词、站位、轴线、惯用手、武器、伤势、道具和场景状态。用户否定单个镜头时，不重写整批，除非该镜头改变了动作因果。

## 输出前验证

逐项执行 [质量检查](references/quality-checklist.md)。如运行环境支持文件和 Python，在保存 Markdown 后运行：

```text
python scripts/validate_storyboard.py <分镜脚本.md>
```

脚本只检查结构、字段、时长、时间轴和批次范围；剧情忠诚、表演、站位与动作因果仍需人工判断。网页端无法执行脚本时，按同一清单手工检查后再输出。

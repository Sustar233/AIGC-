# 输入、事实锁与连续性

## 来源优先级

遇到冲突时按以下顺序采用信息：

1. 用户在当前请求中的明确修改或禁改项。
2. 当前上传的剧本正文与修订稿；较新的明确修订覆盖旧稿。
3. 用户上传的角色、场景、世界观和视觉设定。
4. 当前对话中已经确认的事实与上一批连续性末态。
5. 保守的镜头层面选择。

不得把结构示例、其他项目文件、网络常识或模型记忆当作本项目事实。

## 最小事实锁

正式生成前，在内部锁定与本批有关的字段：

- 项目/集数/场次与剧本版本。
- 本批剧情起点、终点和不可改变结果。
- 场景名称、日夜/内外、固定结构、入口、动线、光源和剧本已有可交互物。
- 全部出场人物、说话者、听者、人物关系和初始站位。
- 角色不可变外观锚点；不要重复扩写完整服装。
- 惯用手、武器、能力源点、能力颜色/材质、当前伤势和限制。
- 关键道具的持有人、位置、状态和变化。
- 台词原文、OS/旁白/现场台词属性、情绪与语速。
- 目标视频模型、画幅、画面风格、生成模式和本次范围。

## 必须暂停确认的情况

只在答案会实质改变成片时提问：

- 同一角色身份、关系或说话者存在互斥版本。
- 台词究竟是 OS、旁白还是现场可听台词不明确，且会影响他人反应。
- 场景、时间或前后事件顺序互相冲突。
- 战斗胜负、伤势、武器状态或能力限制不明确。
- 接触动作、进出场或道具交接在现有空间中无法成立。
- 角色外观、画幅或风格冲突会破坏已确认资产的连续性。

指出冲突的具体句子或事实，只问最小必要问题。不要用一串非关键偏好问题阻断工作。

## 可保守处理的空白

- 未规定的镜头焦段、机位高度和剪辑节奏。
- 不改变剧情的微表情、呼吸、视线和重心细节。
- 未命名的普通环境声。
- 不影响身份识别的背景虚实与光影层次。

场景物件、服装细节、颜色、武器、能力和人物走位不属于可随意补全项。

## 批次连续性末态

每批结尾附：

```markdown
## 批次连续性末态（供下一批续写）
- 已完成范围：
- 人物站位、距离与朝向：
- 相机轴线与左右关系：
- 人物情绪、伤势与行动限制：
- 武器、能力与关键道具状态：
- 场景物件与破坏状态：
- 下一段剧本起点：
```

末态只记录已经由剧本或本批镜头实际形成的状态，不新增剧情。下一批首个单元必须把会入画的末态重新写成物理可见信息。

# 剧本轻量分析流程

你是通用 AI 视频项目的人设与分镜前置分析员。职责不是做完整制片统筹，而是快速发现明确问题、识别新增资产，并为后续视觉资产提示词和 AI 视频分镜补齐必要事实；开始前先读取根目录 `project.json`。

## 使用边界

只有在以下情况使用本技能：

1. 用户导入新剧本或明确要求处理剧本。
2. 用户要求更新数据库。
3. 生成人设或分镜时缺少关键角色、凶兽、灵体、重要道具、能力表现或场景信息。
4. 发现剧本可能存在严重设定冲突，需要先审查。
5. 用户只要求检查错别字、角色名、语病、明显逻辑或前后矛盾。

默认不做以下工作：

- 不生成泛化世界观扩写。
- 不生成与人设/分镜无关的场景图。
- 不展开无关制度、历史、阵营补充。
- 不重复生成已有的人设提示词或场景提示词。
- 不替代 `storyboard-director` 生成正式分镜。

## 快速入口：基础检查

单纯检查当前剧本文字时，只读取当前剧本；角色名可能写错时，再运行：

```powershell
python .agents/skills/script-analyzer/scripts/build_asset_catalog.py --type character
```

该脚本只输出名称、ID、别名、参考状态和详情状态，不建立重复数据库，也不把角色完整设定送入上下文。基础检查只报告：

1. 明显错别字与角色名误写。
2. 明显语病。
3. 明显剧情逻辑错误。
4. 明显前后矛盾。

不要做文学润色、主观审美纠错或强行挑问题。问题按“必须修改 / 建议修改 / 仅供确认”分级；没有明显问题时输出“未发现需要修改的明显错误。”

## 第零步：严重问题审查

每次导入剧本时，先快速审查：

1. 角色身份、能力、外貌是否与数据库冲突。
2. 时间线和场景切换是否影响分镜理解。
3. 台词归属、OS、旁白、潜台词是否容易误拍。
4. 战斗动作是否存在无法生成或明显穿帮风险。
5. 新增生物、灵体、重要道具是否缺少可视化信息。

若发现严重问题，必须暂停并询问用户：“以上问题是否需要我先帮你修正？还是带着这些备注继续解析？”

轻微问题可标记为备注，继续进入提取。

## 第一步：读取最小必要资料

按任务需要读取，不一次性展开全部文件：

- 历史资产初筛：先运行 `scripts/build_asset_catalog.py`，用名称、ID、别名和轻量元数据判断；无法确定时才打开对应数据库中的单条详情
- 人设相关：`项目资料/database/角色.json`、配置指定的最新人设提示词
- 生物/灵体/能力相关：`项目资料/database/生物与灵体.json`
- 重要道具/制度相关：`项目资料/database/道具与制度.json`
- 场景站位相关：`项目资料/database/场景.json`
- 世界规则相关：`项目资料/database/世界观.json`
- 项目主线与集数连续性相关：`项目资料/database/分集剧情.json`；项目级梗概读取顶层 `项目总览`，逐集事实读取 `集数`

## 第二步：提取必要元素

只提取会影响人设和分镜的内容：

1. 新增或变化角色：外貌、发色、体型、服装状态、能力、武器、身份变化。
2. 新增生物/灵体：体型比例、轮廓、材质、运动方式、攻击方式、发光/能量特征。
3. 重要道具：尺寸、材质、携带方式、与角色或剧情动作的关系。
4. 分镜关键场景：空间结构、出入口、遮挡物、可交互物件、多人站位。
5. 战斗关键动作：惯用手、武器轨迹、能力源点、攻击距离、受力反馈。

重要道具只提取以下类别：剧情关键物、多镜持续或跨集复用物、视觉辨识度高的物件、武器、特殊装置，以及后续连续性强依赖的物品。一次性餐具和普通杂物不强制建资产。

## 第三步：对比数据库

1. 名称、ID 或别名精确匹配且无变化：标记“已有”，只引用，不重复生成提示词。
2. 只有近似名称、上下位空间或不完整别名匹配：标记“疑似已有”，读取对应单条详情后再判断。
3. 场景属于已有场景中的新功能区域：标记“新增子场景”，不得简单合并为已有场景。
4. 已存在但变化：标出变化点，提示是否需要更新。
5. 全新元素：标记“新增”，生成符合原数据库结构的最小条目，并说明是否需要同步视觉提示词。
6. 冲突元素：列出数据库设定与新剧本设定的差异，等待用户确认。

## 第四步：最小化更新

只有用户明确要求或新元素确实影响后续人设/分镜时，才更新 JSON：

- 新增/变化角色 -> `角色.json`
- 新增生物/灵体 -> `生物与灵体.json`
- 新增重要道具/制度 -> `道具与制度.json`
- 新增关键场景 -> `场景.json`
- 新增世界规则 -> `世界观.json`
- 新增项目主线或阶段节点 -> `分集剧情.json` 的 `项目总览`
- 新增集数简介、跨集状态变化或处理进度 -> `分集剧情.json` 的 `集数`

不要把项目主线或单集事件重复写入 `世界观.json`；集内镜头站位与末态交给 `memory/storyboard-cache/第X集.md`。

写入前保持 JSON 结构与原文件一致，不做 unrelated 格式化。

分析或审查任务默认不写文件；只有用户明确要求保存/更新，或已授权执行完整的新剧本导入流程时才写入。

## 第五步：可选巧思与视觉资产交接

只有小改动能带来明确收益时，才给出笑点、动作衔接、视觉反差、转场、伏笔或角色反应建议；没有明显收益就跳过，不大改剧情。

新增角色、场景、生物、灵体或重要道具需要生图提示词时，交给 `ai-short-drama-character`，固定输出“精简版 + 扩展版”。精简版只使用本次资料直接确认的内容；扩展版不得改变事实、识别锚点或剧情边界。

## 第六步：输出给用户

输出保持短而可执行：

```markdown
## 剧本解析摘要

### 严重问题
- 无 / [列出需要用户确认的问题]

### 基础检查
| 问题位置 | 原文 | 问题说明 | 建议修改 | 严重程度 |
| --- | --- | --- | --- | --- |

### 历史资产对比
- 角色：已有 / 新增 / 疑似已有
- 场景：已有 / 新增子场景 / 新增 / 疑似已有
- 重要道具：已有 / 新增 / 疑似已有

### 新增或变化的人设元素
- 

### 影响分镜的空间/动作信息
- 

### 必须同步视觉提示词的元素
- 

### 建议下一步
- 生成人设提示词 / 生成第一个分镜单元预览 / 生成完整分镜 / 先修正剧本问题
```

没有对应内容的栏目写“无”或省略；不要为了填满模板扩写。

## 与其他技能协作

1. 人设元素明确后，交给 `ai-short-drama-character`。
2. 分镜需求明确后，交给 `storyboard-director`。
3. 多人场景或战斗场景，只输出必要的站位、动作和风险备注，不在本技能中生成正式镜头脚本。

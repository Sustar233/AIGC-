# AIvideo | 通用 3D 动漫制作工作区

项目定位：本仓库服务于不同题材、世界观和角色体系的 **3D 动漫前期设计与 AI 视频制作**。默认核心产出是角色视觉提示词与可生成的分镜脚本；剧本分析、项目数据库、场景、道具、生物和连续性管理作为支撑流程。任何已有作品都只是当前可选项目，不是 Agent 的默认世界观。

## 核心能力

- 角色、服装、生物、灵体、道具与场景的 3D 动漫视觉提示词
- 普通对白、情绪表演、多人调度、动作场面和剪辑候补分镜
- 剧本可视化分析、资产提取、设定冲突检查与连续性维护
- 面向 Seedance、GPT Image、Seedream 或用户指定平台的提示词适配

## 项目识别与资料边界

1. 优先使用用户明确指定的项目、剧本、集数、角色和输出目录。
2. 用户未指定项目时，从本次源文件所在目录及其邻近的 `database/`、人设提示词和项目说明中识别当前项目。
3. 若源资料位于现有 `剧本文件夹/`，继续兼容该目录，不要求迁移或改名。
4. 不把一个项目的角色、世界观、服装、能力、场景或道具带入另一个项目；跨项目复用只能复用方法和格式。
5. 新项目首次处理时，只补齐影响当前产出的最小信息：项目名、题材/时代、视觉风格、目标平台、画幅、角色与场景资料。信息足够时直接工作，不反复追问。
6. 项目事实优先级：用户本次要求 > 当前项目剧本 > 当前项目数据库/设定集 > 已确认的人设与缓存 > 通用默认值。

## 输出与缓存

- 人设提示词：优先保存到当前项目目录的 `人设提示词.md`。
- 分镜脚本：优先保存到当前项目目录，命名为 `第X集_分镜脚本_*.md`；非剧集项目按用户提供的章节、场次或片段命名。
- 剪辑版候补镜头：与对应分镜放在同一项目目录，并在文件名中标记 `剪辑版`。
- 项目数据库：优先使用当前项目目录的 `database/`；没有数据库时，不为一次性任务强制新建。
- 分镜缓存：使用 `memory/storyboard-cache/<项目标识>/第X集.md`；非剧集任务使用稳定的章节或场次标识。不同项目禁止共享缓存。
- 自定义技能：`.agents/skills/`。

## 默认工作模式

1. **人设与视觉开发**：角色设计、人设图、服装、生物、灵体、道具或场景视觉提示词使用 `ai-short-drama-character`。
2. **分镜导演**：对白、表演、多人调度、镜头设计、连续性和剪辑候补使用 `storyboard-director`。
3. **战斗专项**：仅当出现连续对攻、格挡、追逐、摔投、能力交锋或明确战斗设计时，在分镜剧情边界内调用 `seedance-combat-prompt`。单次能力展示、短促推搡和普通走位由分镜技能直接处理。
4. **剧本分析辅助**：导入新剧本、明确要求更新数据库，或人设/分镜缺少必要设定时，使用 `script-analyzer` 做最小必要提取。
5. **不做无关扩展**：除非用户要求，不生成营销文案、额外世界观、无关资产、无关模板或泛化教程。

## 通用 3D 动漫美术规则

1. 默认基底：高质量 3D 动漫风格，电影级三维动画质感，高精角色模型，清晰材质层次，体积光影，稳定的景深与空间纵深，无明显 2D 勾线，次世代实时渲染质感。
2. 美术方向必须随当前项目变化，可覆盖写实动漫、风格化卡通、国风、古风、科幻、奇幻、都市、校园、机甲、儿童向或其他题材；不得把某一项目的现代装、废土感、能力颜色或城市风格设为通用规则。
3. 用户指定画风、参考作品、渲染方式或平台时优先服从；只继承视觉语言，不擅自复制受保护角色或品牌标识。
4. 画幅读取用户或项目设定；未指定时默认 `16:9` 横屏。竖屏、方形、超宽银幕等需求均可按目标平台调整。
5. 目标平台读取用户要求；未指定时，视频分镜按 Seedance 类 15 秒生成单元组织，图像提示词按主流中文生图模型可读方式编写。
6. 所有视觉设计先锁定跨镜头一致性：体型、脸型、发型、服装轮廓、材质、主色、惯用手、武器、能力源点和尺度关系。

## 人设与资产规则

1. 服装依据当前项目的时代、地域、职业、阶层、文化和剧情状态设计，不默认现代日常装，也不默认废土、古风或科幻。
2. 角色等级、阵营、职业等信息只有在剧本或设定明确要求可视化时，才转化为徽记、制服、肩章或配饰。
3. 默认输出精简版、完整版和可选风格版；用户指定数量或格式时按用户要求执行。
4. 人形角色设定图默认使用纯白背景、自然直立站姿并完整展示身体结构；除非用户明确要求，不使用坐姿、蹲姿、跪姿、倚靠或大幅动态姿势。
5. 人形角色设定图默认不添加椅子、沙发、桌子、环境摆件或无关道具；当前项目明确绑定的武器、能力载体和剧情关键物件可以保留，但不得额外发挥。场景概念图、气氛图和剧情画面按任务类型设置背景与物件。
6. 精简版只使用本次来源中可直接确认的视觉元素，不用数据库延伸、合理推断或审美补全替代缺失事实；纯白背景、自然直立全身和通用 3D 动漫基底属于制图规范。
7. 默认不附加 negative prompt；平台需要或用户明确要求时再提供。
8. 人设提示词文件只保留本次确认的最新版本，不混入其他项目或历史废稿。
9. 生物、灵体、载具、武器、重要道具和关键场景仅在影响当前人设、分镜或连续性时展开，并明确尺度、材质、运动方式和与角色的关系。

## 分镜规则

1. 用户粘贴剧本片段时，默认整段编成一个15秒单元；先优化清晰可听的对白节奏、动作与剪辑。确实过长则先说明预计时长与原因、提出压缩或拆分方案并等待用户选择，不自动拆成两个单元。只有用户已指定多单元范围或同意拆分时，才适用每批最多4个连续单元。
2. 单段默认目标15秒；不得为了凑时长擅自删改台词或用无法听清的极快语速。用户明确指定其他时长时按其要求执行。
3. 新项目或新集首次制作分镜时读取一次必要剧本、人设、场地与数据库资料并建立项目隔离缓存；后续批次优先读取缓存和上一批末态。源资料变化时才刷新受影响内容。
4. 分镜分为快速版、标准版和精细版。未指定时，快速拆解用快速版，正式制作使用标准版，复杂多人、连续战斗和高风险特效使用精细版。
5. 普通对白和过场只保留服务剧情的核心表演动作；完整微表情变化链用于重要台词、情绪转折、反应镜和悬念落点。
6. 多人场景执行人数锁定、站位图谱、轴线锁定、景别降载、画外人员说明和接触动作邻接检查。
7. 战斗场景执行动作切片、力学传导、能力特效绑定、三维轨迹、惯用手/武器锁定和穿帮风险检查。
8. 剪辑版是与正式版节点和时长对齐的平行候补镜头，不默认输出剪辑时间线。
9. 画幅、字幕、文字标识、声音配置和生成平台按项目要求输出，不把某一种规格写成所有项目的硬限制。
10. 发现会改变剧情因果、角色身份或关键设定的严重冲突时暂停并询问用户；轻微问题标注后继续。

## 精简工作流

### 人设与视觉资产

识别当前项目与目标平台 -> 读取必要设定 -> 锁定不可变识别点 -> 选择符合题材的 3D 动漫美术方向 -> 输出所需版本 -> 按需保存到当前项目。

### 分镜

读取当前项目要点、指定片段与必要连续性 -> 判断整段15秒可行性，过长先沟通 -> 直接编写一个完整片段 -> 集中核对台词、时长、表演与连续性 -> 先展示脚本 -> 按项目约定生成预览 -> 简短归档。

### 新剧本导入

执行必要问题审查 -> 提取影响视觉与分镜的角色、场景、生物、道具和动作信息 -> 对比当前项目数据库 -> 最小化更新 -> 按用户需求转入人设或分镜流程。

## 技能职责

- `ai-short-drama-character`：负责通用 3D 动漫角色与相关视觉资产提示词。
- `storyboard-director`：负责剧本单元拆分、表演、多人调度、连续性、正式分镜和剪辑候补。
- `seedance-combat-prompt`：负责战斗单元的招式链、攻防转换、力学传导、战斗运镜和特效轨迹，由分镜技能限定剧情边界。
- `script-analyzer`：负责新剧本的最小必要提取、严重问题审查和当前项目数据库辅助更新。
- `qiuzhi-skill-creator`：仅当用户明确要求创建或更新技能时使用。

## 2026-10-10 工作效率与正文修订（用户最新要求）

- 以上单段15秒与超长先沟通要求覆盖技能里默认自动拆分长台词/片段的流程。不得因技能默认值重新拆成两部分。
- 分镜正文删除“预览代表帧”“素材：LC-…”及类似资产编号、文件路径、裁剪坐标栏目；正文只保留视频模型可理解的镜头、可见动作、台词、声音和必要限制。素材管理放后台。
- 已读技能和稳定资料不反复全文读取；优先使用项目要点与本场缓存，按需查历史。普通短对白不默认做大规模数据库提取、逐像素扫描或多个长说明文件。
- 脚本完成及时展示，再继续预览；独立图片任务在工具允许时并发生成。只在发现实质错误时针对性重做，不承诺无法控制的固定生成耗时。
- 本段原台词需要改动时先沟通；允许在不改变剧情和台词的前提下，通过项目相符的喜剧表演、节奏、音效和运镜增强表达。
